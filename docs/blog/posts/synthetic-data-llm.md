# Synthetic Data for LLM Training: When AI Teaches AI

Synthetic data—data generated by AI models—has become essential for training state-of-the-art language models, raising questions about quality, diversity, and the risks of model collapse.

## Why Synthetic Data?

Human-generated data is:
- **Expensive**: Expert annotation costs $$$
- **Limited**: Finite high-quality sources
- **Biased**: Reflects human limitations
- **Private**: Many valuable datasets can't be shared

Synthetic data addresses these:
- **Scalable**: Generate arbitrary amounts
- **Controllable**: Specify exact properties
- **Diverse**: Cover rare scenarios
- **Safe**: No privacy concerns

## Techniques

### 1. Self-Instruct

Generate instruction-following data from a seed set:

```python
def self_instruct(model, seed_tasks, n_generate=10000):
    tasks = seed_tasks.copy()
    
    for _ in range(n_generate):
        # Sample diverse seed tasks
        examples = random.sample(tasks, k=5)
        
        # Prompt model to generate new task
        prompt = format_generation_prompt(examples)
        new_task = model.generate(prompt)
        
        # Filter low quality
        if quality_check(new_task):
            tasks.append(new_task)
    
    return tasks
```

### 2. Evol-Instruct (WizardLM)

Evolve instructions to be more complex:

```python
EVOLUTION_PROMPTS = {
    "add_constraints": "Add more constraints to this task: {task}",
    "deepen": "Make this task require deeper reasoning: {task}",
    "concretize": "Make this task more specific and concrete: {task}",
    "increase_steps": "Require more reasoning steps: {task}",
}

def evol_instruct(model, task, n_evolutions=3):
    evolved = task
    for _ in range(n_evolutions):
        evolution_type = random.choice(list(EVOLUTION_PROMPTS.keys()))
        prompt = EVOLUTION_PROMPTS[evolution_type].format(task=evolved)
        evolved = model.generate(prompt)
    return evolved
```

### 3. Rejection Sampling

Generate many, keep the best:

```python
def rejection_sampling(model, prompt, reward_model, n_samples=64, k=4):
    # Generate many responses
    responses = [model.generate(prompt) for _ in range(n_samples)]
    
    # Score each
    scores = [reward_model.score(prompt, r) for r in responses]
    
    # Keep top-k
    top_indices = np.argsort(scores)[-k:]
    return [responses[i] for i in top_indices]
```

### 4. Distillation

Transfer knowledge from large to small model:

```python
def distill_dataset(teacher, prompts, temperature=1.0):
    dataset = []
    
    for prompt in prompts:
        # Get teacher's response
        response = teacher.generate(prompt, temperature=temperature)
        
        # Get teacher's token probabilities for soft labels
        soft_labels = teacher.get_probs(prompt + response)
        
        dataset.append({
            "prompt": prompt,
            "response": response,
            "soft_labels": soft_labels
        })
    
    return dataset
```

### 5. Constitutional AI Data

Generate via self-critique and revision:

```python
def constitutional_generation(model, prompt, principles):
    # Initial response
    response = model.generate(prompt)
    
    for principle in principles:
        # Critique
        critique = model.generate(
            f"Does this response follow '{principle}'? Response: {response}"
        )
        
        # Revise if needed
        if "no" in critique.lower():
            response = model.generate(
                f"Revise to follow '{principle}': {response}"
            )
    
    return response
```

## Model Collapse

**The risk**: Training on model-generated data loses diversity over generations.

```
Generation 1: Full distribution
Generation 2: Training on Gen1 output → Narrower distribution
Generation 3: Training on Gen2 output → Even narrower
...
Generation N: Collapsed to single mode
```

**Mitigations**:

1. **Mix with real data**: Always include human data
2. **Diverse generation**: High temperature, diverse prompts
3. **Quality filtering**: Remove repetitive/low-quality samples
4. **Fresh models**: Don't only train on own outputs

## Case Studies

### Phi Models (Microsoft)

- Trained primarily on synthetic "textbook-quality" data
- Small models with outsized capabilities
- Demonstrates synthetic data can improve efficiency

### Orca

- Distilled from GPT-4 explanations
- Focused on reasoning traces
- Smaller model learns *how* to think

### WizardCoder

- Evol-Instruct applied to code
- Generated complex programming problems
- Improved coding benchmarks significantly

## Best Practices

| Do | Don't |
|----|-------|
| Diversify sources and prompts | Use single model/prompt |
| Filter aggressively | Keep all outputs |
| Validate against held-out data | Train blindly |
| Mix with real data | Go fully synthetic |
| Monitor for collapse | Iterate blindly |

---

*Synthetic data is not a replacement for human data—it's an amplifier that lets us extract more value from the human data we have.*
